## Accounts and scope

- **Parent 127038**: every test as a stage/prod pair (≈ 2,000 pairs).
- **Child 222139** (Royal Oakie Records): stage only, checked against the contract (≈ 2,300 tests).
- **Covered:** base, every sort column, granularity, paging, dates, enums / required params, and filters. The child ran the full
  filter × dimension matrix; the parent ran filters on the main dimensions.
- **Not covered:**
  - YouTube, `targetEnterpriseId` and Revenue `metricsByDate`.
  - Parent YEARLY granularity and DAILY on high-cardinality dimensions, plus quarterly/yearly Movement by track. These were kept
    off prod after prod timeouts; their stage-only versions ran.

## Headline

Almost every failure also happens on prod, so it is **pre-existing, not a regression**. The one stage-vs-prod gap is **F-15**: Movement
quarterly/yearly by track/release takes more than 5 s on stage, under 5 s on prod. "Timeouts" in this run are the MCP client's
5 s read timeout (stage spans show HTTP 499 at 5.00 s), not server failures.

## Re-running

The harness expects a `tokens.json` next to `runner.py` (not committed) and `tests/` generated by `gen_chunk*.py`. Results go to `results/`.
It was driven by MCP subagents calling `python runner.py next <chunk>` and saving each tool result verbatim. Prod is paced at ≥ 3 s per
call with a per-sitting cap.
